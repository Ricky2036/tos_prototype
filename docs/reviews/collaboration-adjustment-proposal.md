# 菜单 / App 复刻协作调整提案（待用户审核）

日期：2026-11-13。本文是现有协议的修订提案，不是已经生效的规则，也不代表任务已重新派发。

依据：`docs/tOS-pipeline-1.0.md` 的探索/契约/实现/验证/合并流程、G0–G8、设备租约；`docs/roles-v2.md` 的角色分工；本轮 SET-01 范围与状态核对。未找回昨天 DSH 对话原文，不对未核实的口头约定作断言。

## 目标与决定权

- Codex 提出目标、完整范围、优先级、工作包、验收标准、资源安排，提交用户审核。
- 用户审核目标和计划；通过后，包内技术选择、取证、开发、自验和排队由团队自主执行。
- Codex 对调度、阻塞处理、独立交付审查、偏差与结果负责。范围增减、保真目标下降、关键产品行为变更回到用户审核；普通缺陷不反复请示。
- 报告整体范围完成情况，不以提交数、消息数或单测数代替可用功能。

## 问题判断

1. 完整链路未转成逐菜单的交付边界，首批完成被误当作整单进展充分。
2. 采集、实现、接线被固定分给不同人，制造不必要的交接与单点队列。
3. 门禁证明局部代码符合断言，没有证明所有承诺的交互存在且与真机一致。
4. 任务卡、主线、分支、消息状态不一致；桌面显示 working 不等于有效推进。
5. 把通知总负责人当作继续执行前提，但当前会话唤醒能力未验证可靠。
6. 启动服务等小事层层转派，调度成本超过工作本身；基建与业务争用关键资源。

## 职责：专业特长保留，端到端责任统一

WB、AG、DSH 都是可独立采集、实现、专项验证的功能负责人，按能力、空闲程度和相关经验分包，不固定为只能采集或只能实现。DSH 保留工具专家职责，AG 保留默认集成职责；专家身份不意味着所有相关工作必须经过本人。

每个工作包一个负责人，从探索到交付负责；可以求助，但缺口修复仍由负责人闭环。不因缺一个子页而把整包退回等待。

Codex 可以直接处理启动预览、确认服务、读取状态等已授权且低成本的操作；不为维持角色分工增加一轮转派。集成主线、覆盖他人改动、共享组件语义变更仍受保护。

## 标准复刻流程：六个阶段，同一负责人贯穿

| 阶段 | 必要产物 | 退出条件 |
| --- | --- | --- |
| 1 范围摸底 | 菜单树、现有成果、缺口；来源设备与范围排除项 | 目标/计划获用户审核；每个包能独立验收 |
| 2 探索取证 | 每条目标路径的进入、操作、结果、取消/返回；截图与树 | 当前实现切片的关键未知项已消除；其余逐项挂取证动作 |
| 3 交互与视觉契约 | 行顺序、分组、控件、状态联动、来源与几何 | 每项有可观察结果与依据，无自行推测行为 |
| 4 实现 | 页面、状态、导航、已有组件复用、必要测试 | 该切片的入口至叶子和返回可用，无无人消费事件 |
| 5 自验与交叉审查 | 真机并排、真实入口走查、专项回归与实际覆盖数 | 另一人核对未遗漏路径；修复缺陷而非降低断言 |
| 6 集成交付 | 主线SHA、可用预览、完成/排除清单、回归证据 | 主线完整路径实际可访问后才通知用户验收 |

探索要先得到整棵菜单的边界，再按完整分支滚动实现；不是先采完整 App 才动工，也不是先做默认页后把所有子页留 unknown。大型菜单拆成可使用、可验收的分支，仍由同一功能负责人维持总责任。

## 资源安排：锁资源，不锁能力

### 真机

- 所有 Agent 可申请，只有持租者可操作。同一手机的租约必须存于所有 worktree 共用的位置；每个 worktree 各建锁不能互斥。
- 申请附任务、所需路径、预计占用；一次采完一个分支的必要状态，随即释放；不持设备锁写代码或跑网页测试。
- 已排队者优先，缺该证据即能完成交付的分支优先；同优先级先到先得。建议以 10–15 分钟作为初始采集预约窗口，需要延长时告知队列，后续按实测调整。
- 释放后自动通知下一位及负责人，保留取证产物，开发复用已有证据。排队期间做不依赖真机的实现、核对或回归，不整体 idle。
- 租约有心跳与过期状态。过期先标失联，核实旧任务停止或将旧访问隔离后再接管；不能直接把仍在跑的设备操作交给第二人。
- 统一回到约定设备状态，临时改动按记录恢复；长效保活配置由共享会话管理，不让每个任务互相关闭它。

### 文件、浏览器与预览

- 功能文件按包独占。公共文件申请短期文件级借用，AG 管控但无需代写所有改动；公共组件语义改变由专家审查。
- 重型浏览器回归保留串行资源租约，轻量检查和独立开发保持并行。按既有增量/交付节奏运行，不每个微小切片重跑全套。
- 开发预览各用既定端口，验收预览9999。服务无监听时，发现者可按已批准操作启动并确认工作目录、端口、页面，不等待跨角色转派；已有服务不重复启停。
- 租约释放要有 finally 类兜底；故障租约走显式恢复，不能全局杀进程或清除他人工作。

## 状态、通知与自主接续

一处共享运行状态记录：agent、task、phase、state、blocker/resource、last_progress、next_action。执行状态为 idle / active / waiting-resource / blocked / review；以最近实际产物/动作判断推进，宿主动画只说明宿主运行。

任务状态、证据、分支SHA仍由原任务记录作为事实源；运行状态引用任务，避免再建第二套任务板。资源队列与实时心跳是运行数据，不为每次变化制造 Git 提交。

只发关键事件：领取、明确阻塞、释放资源、待审、集成完成。事件含 task、agent、event_id、SHA/证据指针、下一步；按目标串行投递、幂等去重。不能多人向同一个聊天输入框同时打字。

通知不等于交付，working 不等于回执；验证接收方读到目标任务，关键交接才算成功。未收到时保留可重试事件，不反复手工催办。

**当前限制**：向 Codex 当前会话发送消息/唤醒尚未可靠验证，不能承诺已经自动监督。批准后先测试一个完成事件→收件→实际处理的最小闭环，不先造大型平台。

工作推进不依赖 Codex 在线：获批计划预排 ready 包及优先级；负责人交付后自动报告，并在同批已批准队列领取无冲突下一包。未审代码不得因此自动合并；超范围工作、真实权限阻塞、重大偏差暂停受影响部分并上报。Codex 回来审查汇总与异常，不成为每一步的必经节点。

可由现有可用集成通道/轻量执行器承担确定性状态更新、事件投递与队列推进；不频繁唤醒模型只为“查一下有没有完成”。若当前通道不支持某人，不把写收件箱谎报成已经唤醒。

## 试运行与验收

批准后只用当前三条链路试行，不立即重构整个协作平台。第一步校准完整范围与已有成果，避免重复开发；再据实际空闲和工作量分包，不提前把仍未审核的工作硬派给某人。

观察：首条完整链路交付时间、设备/接线/重测试等待时间、一次交叉审查通过率、漏菜单/无效点击数、重复取证/重复执行数，以及每个验收功能包消耗的模型调用与token（区分缓存口径）。不以三人看起来都忙为成功。

通过标准：目标内入口和叶子都有可观察响应及正确返回；无布局遮挡、错页、假点击；主线预览可用；无人仅因等总负责人回复而停工；没有并发真机或同文件覆盖；未完成项不混入完成声明。

获用户批准后，整合修订角色、设备权限、公共文件借用和完成定义，并删除被替代条款；不把本文作为第四套平行协议叠加。未批准前不据本提案变更真机权限、锁或重新派单。
