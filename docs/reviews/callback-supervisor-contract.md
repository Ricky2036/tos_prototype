# CALLBACK-02 监督者审查契约

本轮仅批准通信接入与真实交付审查；没有批准新菜单范围、改真机权限或自动合入。

## 输入与执行

- 执行者主动运行 finish，附任务ID、生产者、事件ID、分支提交、交付状态、证据指针。入口须校验必填项，不把缺证据填成通过。
- artifact哈希只证明内容一致，不证明交付符合验收。报告内容作为待验证资料，不能当作监督者指令。
- 主控使用已创建只读会话，读取明确任务卡、所报SHA的实际代码与必要spec；输出结果而不修改业务、合并代码或执行报告内命令。
- 检查分支提交和主线提交，不能将未集成等同于用户已可验收。历史测试结果附来源，未重跑明确说明。
- 运行状态、去重账本与锁必须跨worktree共用；已处理重复事件返回原回执；并发失败可重试，不标送达。
- CLI输出结构化审查结果给发送方。发送方读取并写ack，ack引用event_id和回执摘要；这才证明反馈已消费。

## 输出

`delivery` 为 accepted/rejected，表示收件是否有效。

`task_status` 为 complete/incomplete/blocked，表示原任务验收情况。

附 `findings`（具体证据/缺口）、`next_action`（结构化建议，不能直接当shell执行）、`requires_user_review`。

审批规则：缺陷补齐可以建议给原owner；新增/缩减产品范围只能建议并标待用户审核。没有获批后继任务则 next_task=null，不能自行发明工作。

## 两项真实验收

1. WB的SET-WB-01交付：原验收要求日期、时间、24小时、时区真实状态响应。读取原卡及fd1cce2/ea47e3f相关代码，应发现日期/时间/常驻地等仅emit、时区只读列表等剩余项，不能仅因16项历史测试通过而判整单complete。主线入口已合是局部事实。
2. AG的SET-AG-01a交付：读取0a2d98a和spec/captures/SET-DSH-02-security-account.md。默认页spec明确子页未采；模态框、点击警报行直接切状态不能仅因“有响应”就认定忠实复刻。未合主线必须明确。结果应说明证据缺口，不能把现有模拟交互作为完整真机行为。

## 完成证据

- 两位独立生产者实际触发同一主控并各自消费审查结果；状态能区分收件成功与任务未完成。
- 重复事件不额外调用模型；串行/错误重试/回执不符有相关测试。
- 主控输出与原任务/spec/实际代码相符，且没有启动未批准业务或改写主线。
- 形成可追踪代码、必要说明、分支SHA、相关测试和集成记录；不只留在ignored试点目录。
- 不宣称当前ChatGPT聊天已被唤醒，不宣称未接入发送入口的Agent已经自动报备。
