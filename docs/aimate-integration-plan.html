① 结论：能进，但不是 merge

AI Mate 从未进入本仓 git 历史。对全部 841 个提交做全文检索，AI Mate 与 aimate 均 0 命中；对全部 ref 的文件名检索同样 0 命中。归档里的 AI Mate 是在另一条线上做出来的产物，本仓没有任何对应的提交对象。

而且归档侧与当前 HEAD 之间不存在共同祖先。当前历史的根提交 4150774 已包含 DynamicIsland.vue、prayerStore.js、SettingsPrayer.vue，而归档构建对这些字符串全部 0 命中 ⇒ 归档早于根提交。没有共同祖先，git merge 在原理上不成立。

这与上一次「音量 Plus」快照遇到的是同一类问题（那份只落后 31 天），但这次落后得更彻底：归档侧的 var(--safe-top, 44px) 这种兜底写法本身就说明当时 token 表还不存在。

② 与已落地的 OneLeap 的关系

动工前查到的事实：归档里的一半已经被落地了。本工作区的 HEAD 已从评估开始时的 d0c55d5 前进到 1c6ea76，中间落进一个新的应用 src/components/apps/oneleap/OneLeapApp.vue（1610 行，提交 71b2705，2026-09-29）——「OneLeap · 互联中心」，一个以手机为中心节点、四台设备为外围节点的空间拓扑快捷控制界面。

它与本次归档同源：OneLeap 用的照片资产 src/assets/img/oneleap-printer-photo.jpg 与归档里的 ai-mate-assets/photos/photo-01-beach.jpg SHA-256 完全相同（c52c6d5b…36c829）。⇒ 归档的素材已经被另一条线取用过，两边必须对齐后再动手，否则会做出两套重复的设备中枢。

分支状态（核对时）：OneLeapApp.vue 目前只存在于 workbuddy/lane 这条工作线（提交 71b2705），尚未进入 origin/main（核对时 origin/main 的 HEAD 是 d0c55d5）。ACTIVE_TASKS.md 里该条记为 Merged、归属 antigravity/lane、锁定文件一栏为「locks released」。⇒ 设备域已实现是事实，不必重做；但两条工作线并行推进，aimate 接入时必须以同一份设备状态为准，见未决 A2。

  • 设备管理中枢本身是最大的净新增 —— 10 类设备的目录、添加 / 移除、详情页，OneLeap 只有固定 4 台且不可增删。
  • 风扇控制面板（6 档风速 / 摇头 / 等离子 / 童锁 / 定时 / 预约）—— OneLeap 完全没有家电类。
  • 口袋打印机的 7 屏编辑器 —— OneLeap 只有「发起打印流程」的进度条。
  • 录音的转写 / 双语字幕 / 听译 / 面对面翻译 —— OneLeap 只有 3 种拾音模式。
  • AI Mori 独立成应用 —— 初始化向导 + 创作 / 空间 / 设备 / 录音 4 TAB，与设备管理不是同一件事。

两层之间需要对齐的三件事

  • 设备状态要共享一份。oneleap 目前把设备状态放在组件内的 ref（recording / recordSeconds / currentMode / charging）。两层共存后，这些状态应上移到共享 store，否则「在 aimate 里开始录音、oneleap 的快捷卡还显示未录」。
  • 归档的 4 台设备不要再实现一遍。录音充电宝与口袋打印机的设备入口与控制卡已在 oneleap 里，aimate 接入时应复用其状态与动作，只补归档比它多出来的部分（5 种拾音模式、7 屏打印编辑器）。
  • 控制中心的磁贴标签可能要改名。该磁贴现在叫「设备中心」（oneLeap → '设备中心' / 'Device Hub' / 'ডিভাইস হাব'），但它打开的是快捷层；真正的「设备管理」在 aimate。两个名字都指向「设备中心」容易混，见未决 A3。

关于真实录音的落地方式（D3 展开）

档位做什么为什么
真实档
最小闭环		 getUserMedia({audio:true}) → MediaRecorder → Blob → 本地回放。
只在用户主动按下「开始录音」时才请求权限；浏览器不支持或被拒时提示并静默回落到模拟档。		 ① 本地开发服务是 secure context，权限可用；② 录音是这个产品的核心动作，真录一次的说服力远大于波形动画；③ 不引入任何新依赖，全部是浏览器原生 API。
模拟档

目标仓库侧发现并修复的 3 处缺陷

#缺陷影响与修法
1跨语言占位符不一致：cal.monthDay 的中文版把月份写死成 '2月{day}日'，store 因而只传 {day}；英/孟版模板含 {month}切到英语或孟加拉语时渲染出裸占位符。中文是默认语言，只看中文无法发现。已三语统一为 '{month}月{day}日'，并新增一条「同一键的三语占位符集合必须相等」的单测
2device.upgradeAvailable 把版本号写死（三语均为 'V1.3.0 可更新'），而组件已在传 {ver}插值函数对多余参数不报错 ⇒ 固件版本号变更后会静默停在旧值。已改为 '{ver} 可更新'
3foundDevices() 恒发同一个 id（FOUND-<code>），而 enterDevice() 按 id 查重 ⇒ 同一型号永远配不了第二台，uniqueName() 的台号逻辑成为死代码更早的隐患是：对应单测需手改候选 id 才验得到台号逻辑，缺陷被测试掩盖。已改为无状态取「下一个空闲编号」（FOUND-<code> → -2 → -3）；不用计数器是因为计数器必须在「添加设备」入口复位，而复位会让再次添加同一型号重新撞车。附带的正确行为：连点「开始连接」触发两次搜索到达，配对前目录未变 ⇒ 两次算出同一个 id，不会变成两台

重放时必须替换的本仓约定

  • 顶部 64px 是边缘手势热区（.edge-zone，层级 85）。全屏子页头部高度须为 calc(var(--safe-top) + 52px)，否则头部按钮被热区拦走，表现为「点了没反应」。
  • 底部 home-indicator 层级 96，凌驾应用窗口（30）之上。归档惯用的 env(safe-area-inset-bottom) 在浏览器中恒为 0 ⇒ 贴底元素一律 padding-bottom: calc(Npx + var(--home-indicator-zone, 34px))。
  • 折叠面板不用 grid-template-rows: 0fr→1fr：容器高度为 auto 时行高仍被压（实测少 42px），改 max-height。
  • 量尺寸的断言读 getComputedStyle：宿主把整机等比缩放到约 0.941（computed 360px ↔ rect.width 338.73px）。「元素该多大」读 computed；「两元素相对位置」可用 rect；clientHeight / scrollHeight 属未缩放量，不得与 rect 混比。
